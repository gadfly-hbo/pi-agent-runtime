# v0.3 自主运行能力 — 开发与验收合同

用户于 2026-10-07 要求实际解除仅串行工具、固定关闭 thinking，并同步必要代码、标准和包。沿用已确认的公共 SDK/宿主接点测试接缝；不测试 Pi 私有方法。范围：可选并行及逐工具串行覆盖、可配置 thinking、无工具文本入口、必要配置接点和说明。Pi 保持精确 0.86.1；不新增依赖或调用真实 Provider，不迁移现有产品、部署或公开发布。

## 合同

- `toolExecution` 可按运行选择 sequential/parallel，缺省保留 sequential；工具可声明 `executionMode`，批次有 sequential 工具时按 Pi 原生规则整批串行。并行不是事务：已获准并启动的操作不能因另一个操作失败而撤销。继续逐次授权、原子预算、审计、取消和未知效果占用；非法批次在任何工具效果前拒绝。
- 模型显式声明 `reasoning` 能力，运行选择 `thinkingLevel`；缺省/off 不请求启用。所有路由候选须支持请求的能力，不自动关 thinking 来切备用；等级映射以 Pi/Provider 实现为准。thinking 计入同一输出配额，Provider 请求不能扩大 token 上限；Anthropic budget thinking 至少需要 2048 输出空间。必要的供应商签名/屏蔽内容用于协议续接，不进入最终答案或普通审计；跨模型时 Pi 可将未屏蔽思考转为文本，须纳入宿主每次外发授权。
- `runText` 是无工具、单次模型阶段的文本入口，复用全部运行护栏；不要求 JSON，可选宿主文本 validator。主备失败仍可能多次物理尝试。`runWorker` 保留严格 JSON 合同。
- 新选项进入同任务配置身份；不通过改变并行/thinking 或新任务 ID 绕过额度。旧消费者省略新字段时保留旧调用/回放形态；新增字段的精确回放夹具需按合同核对。
- 本轮只开放这些机制，不新增长会话恢复、自动 compaction、Shell/MCP 探索或沙箱。共享 UI 不自动开启 thinking；宿主在已验证模型能力与任务用途下选择参数。

## 验收 IDs

- PT01：真实 Pi 循环两个工具确实并行，模型消费匹配且有序的结果；缺省/逐工具 sequential 保留串行。
- PT02：并行授权/预算/审计/取消/未知效果不被绕过，非法批次不产生效果。
- TH01：两种协议实际请求携带 thinking 参数，输出上限不扩大。
- TH02：签名 thinking 工具回合可续接，最终答案与普通审计不含内部思考，跨模型历史交由 Pi 原生转换。
- TH03：非法 thinking、缺少能力或预算不适合时在效果前拒绝；新配置不能重置同任务身份。
- TX01：无工具文本入口不要求 JSON，文本校验失败停止；原 Worker JSON 负例保留。
- PK01：旧消费者回归、完整离线验证与新包独立消费，Pi 精确依赖和历史包不变。
