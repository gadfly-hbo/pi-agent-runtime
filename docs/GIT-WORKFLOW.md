# GitHub 与双设备同步

仓库：https://github.com/gadfly-hbo/pi-agent-runtime 。用户已明确选择公开仓库；只发布审查后的项目内容。

Git 跟踪源码、测试、锁文件、文档、原型源码及筛选后的 artifacts/public 发布证据。本机历史 artifacts（含失败、截图、备份、机器路径和同步回执）不提交，不删除或改写。文档中历史 artifacts 链接仅在持有原证据的本机可读；当前版本及公开证据从 [README](../README.md#github-与发行包) 进入。公开仓库不是历史证据已全部交付的声明。

0.4.0 已固定的 tgz 以 GitHub Release 附件分发，SHA-256见 artifacts/public/v0.4.0/SHA256SUMS。首次Git化仅增加发布/同步材料，原安装包不重打、不换hash。Git工作区含新增发布文档，因此不承诺重新npm pack产生完全相同的旧发行字节。

## 工作规则

- GitHub main 是共享源码同步基线。开发与规范修改用 codex/ 前缀的独立工作分支，不在 main 写入；一条分支同时只有一个写入端，不覆盖其他任务的未提交工作。
- 日常在所属分支保留小步可回退检查点；仅在任务授权内提交/按需推送，不为每次编辑或普通纠正创建独立 PR。完整可评审的一批结果集中 PR/合并，采用 [README 的验证节奏](../README.md#本地检查)；复用仍有效证据，候选变化补受影响核验。已有 required CI/仓库保护仍须满足；无托管 CI 时只报告实际本地验证。
- 提交、推送、PR/合并、Tag/Release、跨设备同步和消费者升级各按任务授权执行，源码合并不授予包发布权限。仅开发规范修改不触发 SDK 版本升级、重打旧包或发行。
- 同步前核对实际仓库根、当前分支、工作区和进行中的Git操作。已有改动/分叉先报告，不能reset、clean、强推或覆盖。
- 接收端仅快进；相同分支且工作区干净才更新。依赖安装、Provider调用、服务操作和产品采用不由源码同步自动授权。
- sync.targets 是各设备本地Git配置，不提交机器地址。MacBook配置指向Mini已核对的共享SDK目录；未来反向同步须先核对连接和目标。
- 首次接入已有非Git材料目录时，先完整备份并验证逐文件hash，再在原路径接入Git；保留本地历史材料，不创建平行开发副本。
- 获准跨设备源码交付时读回涉及设备/GitHub 的 branch、commit；交付发行包还核对实际 bytes/完整 hash、适用消费者及下载结果。包发布与产品采用分开，不自动同步、安装或升级消费者。
- 在研任务在自然安全边界读回并明确采用规则，不强制合并/切换代码基线；保留原任务、分支、WIP、冻结合同、失败/UNKNOWN、资源与停止线。发布或同步均不自动恢复任务。
