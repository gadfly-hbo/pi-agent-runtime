## 三个模块

| 模块（名称暂定，不是已发布包） | 负责 | 不负责 |
| --- | --- | --- |
| 配置核心 / headless | 普通平台类型、草稿校验、路由快照、能力匹配、标准错误 | 真实密钥、具体数据库、UI 框架、Pi 内部类型 |
| Runtime SDK | 将生效快照装配到 Pi Adapter，任务授权/预算/审计，受限故障切换 | 管理设置页、业务任务完成判定、产品数据语义 |
| 配置 UI | Provider/模型编辑、主备排序、草稿/生效状态、检查结果展示 | 直接调用 Pi 或 Provider、保存密钥、决定任务授权 |

依赖方向：UI → 配置核心；Runtime → 配置核心 + Pi Adapter；产品宿主 → 三者并装配存储/凭据/授权。配置核心不反向依赖 Runtime，UI 不导入 Node 或 Pi。

同栈产品建议直接引用首版 React UI；不同栈引用 headless 校验与合同，重用行为但不强制 React。原型是零框架静态页面，**还不是可安装 React 包**。不建设统一账号、全局配置服务器或跨产品自动同步。

## 最小宿主接缝（逻辑接口提案）

配置 UI 接收当前草稿、生效版本、连接检查状态和宿主操作结果；变更通过回调交回宿主。建议操作：读取配置、保存草稿、校验并生效、更新/删除凭据、明确发起模型检查。精确 TypeScript 方法名属于后续工程细化。

- 普通配置不含明文 API Key。凭据输入仅交给宿主后端；读回只有“已设置/未设置/不可用”和不透明引用，不读回原值。正式版不默认提供密钥回显。
- Provider 是连接配置，不是任务主备角色。Model 隶属一个 Provider。Route 指向稳定的内部 Model 身份，而不是显示名。
- 校验并生效必须在宿主重复执行，不能信任浏览器校验；按期望版本并发检查，失败保留旧生效版本。
- 模型检查是独立、明确授权的外发操作；宿主返回检查范围、时间、所检查的配置指纹和安全错误。费用/测试输入/目的端须先展示。检查不调用业务工具。
- 自定义 URL 不能把任意网络访问变成通用代理。宿主按部署边界校验端点、跳转、HTTPS 和本地地址权限；个人本地配置不自动赋予云端访问内网权限。API Key 不随重定向转发到其他源。
- UI 的“启用”仅表示候选可用；任务实际允许哪些 Provider、端点和数据仍由宿主授权。不能由设置页替换产品数据出境策略。

## 对象与逻辑字段组（待批准）

| 对象 / 粒度 / 所有者 | 字段含义、必选与默认 | 关系与生命周期 |
| --- | --- | --- |
| Provider：一个连接配置；产品宿主所有 | 内部 ID（创建后稳定）；显示名（必选，不当唯一键）；Base URL（必选，合法 URL）；协议（必选，仅两种已支持值，不推断）；enabled（显式值）；credentialRef（可空，空=未设置，不代表免认证） | 1:N Model；编辑不直接改运行中的快照；引用中的删除由宿主拒绝或显式重配 |
| Model：一个 Provider 下的模型配置；产品宿主所有 | 内部 ID（稳定）；Provider ID（必选）；Provider 原始 model ID（必选、原样）；显示名（可选，空时展示 model ID）；contextWindow（正整数、必选，不猜默认）；声明工具能力（显式 true/false）；enabled（显式） | 不同 Provider 可有同名 model ID；同 Provider 的重复 model ID 拒绝；内部引用不能靠改名迁移 |
| Route：一个用途配置；产品宿主所有 | primary Model ID（恰好一个）；fallback Model IDs（有序，至少一个，无重复）；用途所需能力由产品传入，不由 UI 推测 | 不允许主备重复；同 Provider 的不同模型可作备用；选择不满足该用途能力的候选被拒绝 |
| Draft：一次设置编辑状态；产品宿主所有 | 配置内容 + 编辑基线版本；不完整草稿允许保存 | 保存不是生效；放弃回到当前生效版；离开有未保存内容须提示 |
| Active snapshot：一次生效发布；产品宿主所有 | 不可变版本/指纹 + Provider/Model/Route 内容 + 凭据引用；生效时间由宿主记录 | 新任务绑定该版；运行中任务继续原版；旧版本可用性依宿主保留策略，不能宣称跨进程恢复已具备 |
| Check result：针对一个 Model 配置指纹的观察；产品宿主所有 | 未检查/检查中/通过/失败；检查时刻、范围、指纹、安全原因；声明能力与验证能力分别表示 | 改端点/协议/model ID/凭据/相关能力后失效；连通性检查不能证明工具执行能力 |

凭据本身是宿主安全存储里的独立对象，不建立共享明文表。版本、指纹和审计不包含密钥；凭据轮换由宿主按任务绑定/引用策略处理，不能承诺可回放旧密钥。检查记录不是授权证明。配置不含业务证据、业务语义或会话历史。

不规定 SQL 表、索引、迁移布局或企业租户字段。本阶段粒度仅到逻辑对象和版本；查询视图为 UI read model，不增加业务事实权威。

## Runtime 必须补齐的接点（本轮未实现）

1. v0.1 `RuntimeOptions.model` 是单模型；新增路由快照输入与装配，保持旧入口。
2. 当前预算 `reserveModel()` 预留全部剩余输出 token。失败用量未知时不能返还；直接套 fallback 会把额度耗尽。需明确每次尝试上限与请求级累计额度，允许在剩余额度内尝试备用，不能靠切换模型重置预算。安全锁定剩余不足时停止。
3. 当前任务配置指纹含单模型；需绑定同一批准路由快照/工具/额度，同时审计每次实际模型、尝试序号、错误类别和用量已知性。改变生效版不改已绑定任务。
4. 不能默认不同 Provider 接受所有已有消息；适配层负责支持的消息转换，工具调用 ID 与执行结果不丢失。未知副作用不重放。上下文窗口不足时明确拒绝，不偷偷截断。
5. 能力/鉴权失败、非法输出、审计失败等不默认统统重试；具体可切换错误清单与负例在正式实现前固化。当前 SDK **没有**多模型 fallback、凭据仓库或配置 UI。
